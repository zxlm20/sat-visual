# 前端负载均衡算法对接指南

本文档供前端开发人员直接对接负载均衡算法选择、参数配置、执行状态和调度结果。
后端插件开发与内部调度协议见 [3.11 负载均衡算法预留服务接口](./3.11-load-balancing-api.md)。

## 1. 快速说明

服务地址：

```text
http://192.168.5.11:30080/api/lb
```

前端需要遵守以下约定：

- 新页面统一使用字符串 `algorithm_id`，不要使用旧数字 `policy_id`；
- 算法切换只影响下一项任务，不中断当前任务，也不会重启 dispatcher；
- `desired` 是前端为下一任务选择的配置；
- `runtime` 是 dispatcher 最近一次真实执行状态；
- 只有 `runtime_available=true` 的算法允许切换；
- 参数值必须保持正确的 JSON 类型，例如数字提交为 `2`，不能提交为 `"2"`；
- 切换成功后的提示文案建议使用“已保存，从下一任务开始生效”。

建议通过环境变量配置服务根地址：

```env
VITE_API_BASE_URL=http://192.168.5.11:30080
```

## 2. 前端核心接口

| 用途 | 方法 | 路径 |
|---|---|---|
| 查询算法及参数定义 | GET | `/algorithms` |
| 只保存某个算法的参数 | PUT | `/algorithms/{algorithm_id}/config` |
| 切换下一任务使用的算法 | POST | `/switch` |
| 查询期望配置和最近运行状态 | GET | `/current` |
| 查询算法执行状态 | GET | `/status` |
| 查询最近一次有效调度结果 | GET | `/results/latest` |

普通算法选择页面只需要以上 6 个接口。

## 3. 内置算法

| 算法 ID | 显示名称 | 参数 |
|---|---|---|
| `round_robin` | 轮询调度 | 无 |
| `single_node` | 单节点 / 无负载均衡 | `target_node` |
| `jsq` | 最短队列优先 | 无 |
| `ect` | 最早完成时间优先 | 无 |
| `difficulty_ewma` | 难度感知 + EWMA | `speed_alpha` |
| `p2c` | 双选择随机 | `sample_size` |
| `adaptive_weight` | 自适应权重 | 4 个数值参数 |
| `work_stealing` | 工作窃取 | 无 |

参数说明：

| 算法 | 参数 | 类型 | 默认值 | 限制 | 含义 |
|---|---|---|---|---|---|
| `single_node` | `target_node` | string | `lnode01` | 必填 | 目标物理节点 |
| `difficulty_ewma` | `speed_alpha` | number | `0.2` | 0～1 | 速度 EWMA 更新系数 |
| `p2c` | `sample_size` | integer | `2` | 1～32 | 每次参与比较的随机候选节点数 |
| `adaptive_weight` | `alpha` | number | `0.2` | 0～1 | 权重更新系数 |
| `adaptive_weight` | `target_latency_per_cost` | number | `0.1` | ≥ 0.000001 | 单位难度目标延迟 |
| `adaptive_weight` | `failure_penalty` | number | `0.2` | 0～1 | 失败惩罚 |
| `adaptive_weight` | `retry_penalty` | number | `0.05` | 0～1 | 重试惩罚 |

前端不要把这张表硬编码成唯一事实来源。实际表单仍应以后端
`GET /algorithms` 返回的 `parameters` 为准。

## 5. Axios 接口封装

可将以下内容保存为 `src/api/loadBalancing.ts`：

```ts
import axios from "axios";

import type {
  AlgorithmListResponse,
  CurrentAlgorithmResponse,
  ExecutionStatus,
  LatestResultResponse,
  ParameterValue,
  SaveConfigurationResponse,
  SwitchResponse,
} from "./loadBalancing.types";

const backendBase = (
  import.meta.env.VITE_API_BASE_URL ??
  "http://192.168.5.11:30080"
).replace(/\/$/, "");

export const loadBalancingApi = axios.create({
  baseURL: `${backendBase}/api/lb`,
  timeout: 10_000,
});

export async function getAlgorithms(): Promise<AlgorithmListResponse> {
  const response =
    await loadBalancingApi.get<AlgorithmListResponse>("/algorithms");
  return response.data;
}

export async function saveAlgorithmConfig(
  algorithmId: string,
  parameters: Record<string, ParameterValue>,
): Promise<SaveConfigurationResponse> {
  const response =
    await loadBalancingApi.put<SaveConfigurationResponse>(
      `/algorithms/${encodeURIComponent(algorithmId)}/config`,
      { parameters },
    );
  return response.data;
}

export async function switchAlgorithm(
  algorithmId: string,
  parameters: Record<string, ParameterValue>,
): Promise<SwitchResponse> {
  const response = await loadBalancingApi.post<SwitchResponse>("/switch", {
    algorithm_id: algorithmId,
    parameters,
  });
  return response.data;
}

export async function getCurrentAlgorithm(): Promise<CurrentAlgorithmResponse> {
  const response =
    await loadBalancingApi.get<CurrentAlgorithmResponse>("/current");
  return response.data;
}

export async function getExecutionStatus(): Promise<ExecutionStatus> {
  const response =
    await loadBalancingApi.get<ExecutionStatus>("/status");
  return response.data;
}

export async function getLatestResult(): Promise<LatestResultResponse> {
  const response =
    await loadBalancingApi.get<LatestResultResponse>("/results/latest");
  return response.data;
}
```

`PUT /config` 只保存参数，不切换算法；`POST /switch` 会校验并保存本次参数，
同时修改下一任务使用的算法。如果页面只有“应用”按钮，可以只调用
`POST /switch`。


### 6.5 查询执行状态

```http
GET /api/lb/status
```

状态含义：

| state | 前端显示 | 是否终态 |
|---|---|---|
| `idle` | 尚无算法执行记录 | 是，但不代表刚切换的算法已执行 |
| `running` | 正在调度/下发 | 否 |
| `succeeded` | 调度成功 | 是 |
| `fallback_succeeded` | 目标算法失败，轮询回退成功 | 是 |
| `failed` | 调度或下发失败 | 是 |

`running.phase`：

- `algorithm_execution`：算法正在计算并校验分配结果；
- `result_dispatch`：结果已校验，正在写入 Redis 任务流；
- `output_validated=true`：输出完整性校验已通过。

回退示例：

```json
{
  "schema_version": 1,
  "state": "fallback_succeeded",
  "execution_id": "job-20260720:1",
  "job_id": "job-20260720",
  "config_revision": 1,
  "requested_algorithm_id": "custom_demo",
  "effective_algorithm_id": "round_robin",
  "fallback_used": true,
  "fallback_reason": "missing tile assignments: r1_c2",
  "updated_at": "2026-07-20T08:45:00Z"
}
```

前端应同时展示“请求算法”和“实际算法”，不能把回退成功展示为目标算法成功。

## 7. 动态参数表单

### 7.1 初始化参数

```ts
import type {
  AlgorithmDescriptor,
  ParameterValue,
} from "./loadBalancing.types";

export function initialParameters(
  algorithm: AlgorithmDescriptor,
): Record<string, ParameterValue> {
  const result: Record<string, ParameterValue> = {};
  const saved = algorithm.configured_parameters ?? {};

  for (const [name, definition] of Object.entries(algorithm.parameters)) {
    if (Object.prototype.hasOwnProperty.call(saved, name)) {
      result[name] = saved[name];
    } else if (definition.default !== undefined) {
      result[name] = definition.default;
    }
  }

  return result;
}
```

优先级：

1. `configured_parameters`；
2. 参数定义中的 `default`；
3. 没有默认值时保持未填写。

### 7.2 控件映射

| 参数定义 | 推荐控件 |
|---|---|
| 存在 `enum` | Select |
| `string` | Input |
| `integer` | InputNumber，限制为整数 |
| `number` | InputNumber |
| `boolean` | Switch/Checkbox |

### 7.3 类型转换和校验

```ts
import type {
  ParameterDefinition,
  ParameterValue,
} from "./loadBalancing.types";

export function normalizeParameter(
  name: string,
  definition: ParameterDefinition,
  rawValue: unknown,
): ParameterValue | undefined {
  if (rawValue === "" || rawValue === null || rawValue === undefined) {
    if (definition.required) {
      throw new Error(`${name} 为必填参数`);
    }
    return undefined;
  }

  let value: ParameterValue;

  if (definition.type === "integer") {
    value = Number(rawValue);
    if (!Number.isInteger(value)) {
      throw new Error(`${name} 必须是整数`);
    }
  } else if (definition.type === "number") {
    value = Number(rawValue);
    if (!Number.isFinite(value)) {
      throw new Error(`${name} 必须是数字`);
    }
  } else if (definition.type === "boolean") {
    value =
      typeof rawValue === "boolean"
        ? rawValue
        : rawValue === "true";
  } else {
    value = String(rawValue);
  }

  if (
    typeof value === "number" &&
    definition.minimum !== undefined &&
    value < definition.minimum
  ) {
    throw new Error(`${name} 不能小于 ${definition.minimum}`);
  }

  if (
    typeof value === "number" &&
    definition.maximum !== undefined &&
    value > definition.maximum
  ) {
    throw new Error(`${name} 不能大于 ${definition.maximum}`);
  }

  if (
    definition.enum &&
    !definition.enum.some((item) => item === value)
  ) {
    throw new Error(`${name} 不在允许范围内`);
  }

  return value;
}

export function normalizeParameters(
  definitions: Record<string, ParameterDefinition>,
  formValues: Record<string, unknown>,
): Record<string, ParameterValue> {
  const result: Record<string, ParameterValue> = {};

  for (const [name, definition] of Object.entries(definitions)) {
    const value = normalizeParameter(name, definition, formValues[name]);
    if (value !== undefined) {
      result[name] = value;
    }
  }

  return result;
}
```

后端仍会进行最终校验。前端校验用于及时提示，不能代替后端校验。

## 8. 推荐页面调用流程

### 8.1 页面初始化

```ts
const [{ algorithms }, current] = await Promise.all([
  getAlgorithms(),
  getCurrentAlgorithm(),
]);

const selectedAlgorithmId = current.desired.algorithm_id;
const selectedAlgorithm = algorithms.find(
  (item) => item.algorithm_id === selectedAlgorithmId,
);
```

页面应：

1. 选中 `current.desired.algorithm_id`；
2. 初始化对应参数；
3. 显示当前配置版本 `desired.revision`；
4. 显示最近运行状态 `current.runtime.state`；
5. 禁用所有 `runtime_available=false` 的算法。

### 8.2 用户点击“应用”

```ts
import type { AlgorithmDescriptor } from "./loadBalancing.types";

export async function applyAlgorithm(
  algorithm: AlgorithmDescriptor,
  formValues: Record<string, unknown>,
) {
  if (!algorithm.runtime_available) {
    throw new Error("该算法尚未由 dispatcher 加载");
  }

  const parameters = normalizeParameters(
    algorithm.parameters,
    formValues,
  );

  return switchAlgorithm(algorithm.algorithm_id, parameters);
}
```

成功后显示后端返回的 `message`，并更新：

- 当前选择；
- 参数；
- `revision`；
- 生效范围 `next_job`。

### 8.3 轮询下一任务执行状态

```ts
const TERMINAL_STATES = new Set([
  "succeeded",
  "fallback_succeeded",
  "failed",
]);

function delay(ms: number, signal?: AbortSignal): Promise<void> {
  return new Promise((resolve, reject) => {
    const timer = window.setTimeout(resolve, ms);
    signal?.addEventListener(
      "abort",
      () => {
        window.clearTimeout(timer);
        reject(new DOMException("Aborted", "AbortError"));
      },
      { once: true },
    );
  });
}

export async function waitForRevision(
  revision: number,
  options: {
    intervalMs?: number;
    timeoutMs?: number;
    signal?: AbortSignal;
  } = {},
): Promise<ExecutionStatus | null> {
  const intervalMs = options.intervalMs ?? 2_000;
  const timeoutMs = options.timeoutMs ?? 300_000;
  const deadline = Date.now() + timeoutMs;

  while (Date.now() < deadline) {
    const status = await getExecutionStatus();

    // 切换后可能暂时仍显示上一个任务，必须用配置版本匹配下一任务。
    if (
      status.config_revision === revision &&
      TERMINAL_STATES.has(status.state)
    ) {
      return status;
    }

    await delay(intervalMs, options.signal);
  }

  // null 表示等待期内没有使用该版本的新任务完成，不代表算法失败。
  return null;
}
```

不要在切换成功后把旧任务的 `succeeded` 当作新算法的执行结果。必须比较
`config_revision`。

## 9. 状态展示建议

| 状态 | 颜色建议 | 文案 |
|---|---|---|
| `idle` | 灰色 | 等待任务 |
| `running` | 蓝色 | 调度执行中 |
| `succeeded` | 绿色 | 调度成功 |
| `fallback_succeeded` | 橙色 | 已回退并成功 |
| `failed` | 红色 | 调度失败 |

`fallback_succeeded` 必须展示：

- `requested_algorithm_id`；
- `effective_algorithm_id`；
- `fallback_reason`。

`failed` 优先展示：

1. `error`；
2. `fallback_error`；
3. 通用文案“负载均衡调度失败”。

## 10. 错误处理

| HTTP 状态码 | 前端处理 |
|---|---|
| 400 | 管理接口提交内容非法或算法重复，显示 `detail` |
| 404 | 算法不存在，提示后重新加载算法列表 |
| 409 | dispatcher 未加载该算法，禁用应用按钮 |
| 422 | 参数类型、范围、枚举或必填项错误，显示到参数表单 |
| 5xx | 保留当前页面选择，提示稍后重试 |
| 网络错误/超时 | 请求 `GET /current` 重新确认是否已经切换 |

Axios 错误提取：

```ts
import axios from "axios";

export function getApiErrorMessage(error: unknown): string {
  if (!axios.isAxiosError(error)) {
    return error instanceof Error ? error.message : "未知错误";
  }

  const detail = error.response?.data?.detail;
  if (typeof detail === "string") {
    return detail;
  }

  if (Array.isArray(detail)) {
    return detail
      .map((item) => item?.msg)
      .filter(Boolean)
      .join("；");
  }

  if (!error.response) {
    return "无法连接负载均衡服务";
  }

  return `请求失败（HTTP ${error.response.status}）`;
}
```

如果 `POST /switch` 超时，不要立即重复提交。先调用 `GET /current`：

- `desired.algorithm_id` 和参数已经匹配：视为切换已保存；
- 不匹配：允许用户重试。

## 13. 浏览器联调顺序

1. 请求 `GET /algorithms`，确认返回 8 个算法；
2. 请求 `GET /current`，初始化当前选择；
3. 选择 `p2c`，输入 `sample_size=2`；
4. 请求 `POST /switch`；
5. 确认响应 `effective_scope=next_job`；
6. 再次请求 `GET /current`，确认 `desired.algorithm_id=p2c`；
7. 提交一项新任务；
8. 每 2 秒请求 `GET /status`；
9. 使用 `config_revision` 确认状态属于本次切换；
10. 进入终态后请求 `GET /results/latest`。

服务端快速联调命令：

```bash
export BASE_URL=http://192.168.5.11:30080

curl -fsS "$BASE_URL/api/lb/algorithms" | python3 -m json.tool

curl -fsS -X POST "$BASE_URL/api/lb/switch" \
  -H "Content-Type: application/json" \
  -d '{"algorithm_id":"p2c","parameters":{"sample_size":2}}' \
  | python3 -m json.tool

curl -fsS "$BASE_URL/api/lb/current" | python3 -m json.tool
curl -fsS "$BASE_URL/api/lb/status" | python3 -m json.tool
curl -fsS "$BASE_URL/api/lb/results/latest" | python3 -m json.tool
```
